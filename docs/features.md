# Mojito Feature Matrix

This is the authoritative summary of language support. Update it in the same
change that alters a feature's status. [`grammar.md`](../grammar.md) remains authoritative for
surface syntax; the tests remain authoritative for detailed behavior.
The machine-checkable comparison with pinned Mojo—including explicit divergences
and exclusions—lives in [`conformance/parity.tsv`](../conformance/parity.tsv).

Status meanings:

- **Run** — accepted by the production compiler and executed by the register VM.
- **Check** — represented and checked, but has no independent runtime behavior.
- **Parse** — preserved in the AST but deliberately rejected before execution.
- **No** — not reliably accepted even as syntax.

| Area | Feature | Status | Boundary / notes |
|---|---|---:|---|
| Frontend | Indentation, continuations, comments, numeric/string literals, Mojo escapes | Run | Includes current radix/decimal/exponent separators, `Byte == UInt8`, raw and triple forms, and same-line or indented adjacent strings. Diagnostic parsing can report multiple statement-level errors. |
| Types | Exact numeric literals and scalar materialization | Run | Source `IntLiteral` values use arbitrary-precision integers; finite `FloatLiteral` values use exact rationals with negative-zero preservation. Literal-only arithmetic remains exact through compile-time evaluation. Checked HIR records the contextual boundary, MIR emits `MaterializeLiteral`, integer targets wrap to their width, and floating targets round once directly to binary32/binary64. |
| Frontend | T-strings | Run | Prefix order/case and raw/triple combinations are accepted; nested lexical structure is respected. Interpolations require `Writable`, convert through `String`, and concatenate in source order. Lazy self-hosting remains in Complete MIR-Schema-Prerequisite CPU Semantics. |
| Frontend | Walrus `:=` | Run | Evaluates once and introduces a function-scoped binding while producing the value. |
| Modules | File-scope declarations and runtime entry | Run | Runtime statements at file scope are rejected; execution begins in zero-argument `main()`. |
| Bindings | Typed/inferred `var` (required), late initialization, assignment | Run | `var` is the sole declaration form: a bare `x = e` (or `a, b = e`) targeting a name not in scope is rejected (`AssignToUndeclared`). `var` is **block-scoped** — a declaration inside a nested block is not visible after it. Reads require initialization on every reaching path (path joins retain a maybe-uninitialized state unless every reachable path assigns it); same-scope redeclaration and type changes are rejected. |
| Bindings | Field/index places, augmented assignment, tuple unpacking | Run | Place expressions evaluate indexes once. Augmented assignment on a user-defined value dispatches to its dedicated in-place dunder (`x += y` → `x.__iadd__(y)`, and `__isub__`/`__imul__`/`__itruediv__`/`__ifloordiv__`/`__imod__`/`__ipow__`) as a checked `mut self` method call for variables, projected fields, and nominal-subscript elements, mutating the receiver in place; Mojo does not fall back to `__add__`. A missing in-place dunder, an immutable receiver, and a mismatched right-hand side are rejected, and a raising in-place dunder participates in ordinary `try` handling. Native scalar targets keep the builtin read-modify-write. |
| Bindings | Local `ref name = place` | Run | Aliases variable/field/index storage; indexed places bind once; persistent CFG loans enforce exclusivity through last use. |
| Control flow | Loop `else`, `for ref`, context managers | Run | `break` bypasses loop `else`; concrete List-place reference iteration retains the live owner and writes through element handles, but remains a checked compiler bridge rather than generic origin-parameterized `Iterable` dispatch; `with` executes checked enter/exit calls, including raising exits. |
| Calls | Defaults, keywords, `/`, `*`, homogeneous `*args` | Run | One structural contract serves free, method, static-method, and hand-written constructor calls in the checker and VM. |
| Calls | Homogeneous `**kwargs` and `**kwargs^` forwarding | Run | Free, generic, instance, static, and bounded-trait calls materialize an owned, insertion-ordered `StringDict[T]`. Forwarding consumes it through the shared binder, specialization, duplicate, origin, ownership, and effect checks. |
| Calls | Heterogeneous `*args: *ArgTypes` | Run | Per-element bound checking, an explicit checked runtime-pack ABI with private heterogeneous `Value::Tuple` storage, and compile-time `args.__len__()` iteration/indexing run for literal and directly constructed arguments. Before generating a specialization, the call-site conformance diagnostic identifies the one-based failing element, its concrete type, the pack, and the unsatisfied trait. A pre-check resolver assigns stable value/type binding identities, so pack spreading and type expansion respect nested definitions, lexical blocks, loops, comprehensions, sibling methods, and empty packs. Nested templates have scope-qualified identities, specialize independently at their lexical declaration, lift recursively at arbitrary depth, and preserve captures/defaults/keywords/named results. A complete forwarded pack follows the fully supplied fixed positional prefix and precedes a keyword/default tail; its private pack collector moves as one value without copying linear elements. Type and value packs may be interleaved with semantic-only `Origin`/`OriginSet` parameters; a pack consumes only its source-layout segment, so a named Origin suffix remains at the rewritten call. A second spread or explicit positional overflow after the spread is rejected, matching the pinned nightly. Specialization exposes the concrete type of each statically indexed pack element; ordinary tuple-valued homogeneous variadics remain nominal `List` collectors. |
| Calls | Generic callable constraints and callable-value parameters | Run | `F: def(T) -> T` is retained as a dependent checked constraint, makes `F` callable inside the generic body, and validates a monomorphic contract against one monomorphic function type or nominal callable struct. A contract with its own `def[...]` list instead accepts an alpha-equivalent generic function, retaining binder arity, bounds, conventions, effects, reference origins, and invocation defaults. Compatibility is directional: a nonraising/read-only implementation may satisfy a raising/mutable contract, while ownership-changing conventions and reference-origin contracts remain exact. An explicit environment qualifier on the right-hand side (`callback: def(...) thin` or `capturing[...]`) declares a compile-time callable-value parameter; `OriginSet`, `capturing[_]`, `capturing[origins]`, and the infer-only `//` marker are retained, and the supplied function or closure is reified into a hidden typed runtime local for indirect calls. Callable-value defaults are symbolic selected-function, earlier-parameter, or compile-time-conditional plans evaluated in declaration order. Comptime specialization bakes the scalar/type/pack values it inspects while retaining callable and Origin arguments on the residual signature and call site; `CtValue` deliberately has no function or closure variant, and arbitrary callable CTFE is not implied. |
| Calls | Callable capture-origin contracts | Run | Checked function types distinguish unqualified, `thin`, and `capturing` environments. Materialized closures carry a canonical concrete origin set with read/write access per captured owner; `OriginSet` parameters and inference placeholders remain symbolic until a concrete callable is supplied. These dependencies participate in substitution, nominal conformance, origin escape checking, checked HIR, typed MIR declarations, and direct, indirect, method, and nominal subscript capture effects, so persistent-loan analysis sees mutations performed by a directly called closure or a non-escaping callable argument. An unqualified `def(...)` contract accepting a stateful downward funarg is a Mojito extension over the pinned nightly; explicit `capturing[...]` is the parity spelling. |
| Calls | Method/generic argument-binding parity | Run | Includes ordinary-parameter write-back. |
| Calls | User-defined static methods | Run | Uses the same positional/default/keyword ABI without a receiver slot. |
| Calls | Callable expressions / first-class function values | Run | Non-capturing, generic, origin-specialized, and contextually selected overloaded functions can be stored, passed, and indirectly invoked with checked raising and capture effects plus reference returns. Explicit Origin arguments participate in direct overloaded and generic calls, combine with explicitly supplied ordinary generic arguments in function values, and select an overloaded function value when an expected `def(...)` type identifies one candidate; an uncontextualized overloaded value remains ambiguous. User structs are callable only when they nominally conform to a matching `def(...)` contract and implement `__call__`; callable generic parameters, environment constraints, `mut`/`ref` conventions, origin-bearing results, the receiver place, and the exact signature-qualified `__call__` target survive conformance and indirect lowering, including same-arity overload sets. Captured nested Origin specialization remains a documented Mojito extension over the pinned nightly. |
| Calls | Named `out` results | Run | A free function's single `out` parameter is a caller-transparent result slot and must be initialized before fallthrough or bare return. |
| Conventions | `imm`/legacy `read`, `var`, `mut`, `ref` parameters and `ref self` | Run | `imm` and its temporary compatibility synonym `read` share immutable-reference semantics. Copyable immutable arguments overlapping a `mut` argument are materialized; non-Copyable aliases remain errors. |
| Conventions | `out self`, named `out` results, `deinit self` | Run | Lifecycle receivers and a single free-function named result are supported. |
| Lifecycle | `ImplicitlyDeletable`, unified copy/move initialization, and `@implicit` constructors | Run | Ordinary values are implicitly deletable; an explicitly false conditional conformance makes a type linear. Legacy unified-initializer spellings remain documented compatibility extensions. |
| Lifecycle | `@explicit_destroy` | Run | The required string argument customizes linearity diagnostics but does not itself make a type linear. Named `deinit self` methods discharge path-sensitive obligations. Abandonment, overwrite, partial/double/conditional destruction are rejected; raising destruction preserves the value for an `except` fallback and automatic `DropVar` destruction is suppressed. |
| Functions | Recursion and conservative return checking | Run | Sibling forward references and mutual recursion are rejected. |
| Functions | Non-escaping closures | Run | Current capture lists use `{imm name}`, `{mut name}`, `{ref name}`, `{var name}`, move/default forms, or `{}`. Reference captures retain frame/slot handles without imposing a declaration-to-call loan, so `imm` observes intervening outer updates; `var` copies at declaration, and move capture transfers at declaration. Checked captures retain exact owner identity, storage type, and convention even when unused. Lexical declarations lift recursively at arbitrary depth while preserving materialized sibling snapshots, ancestor forwarding, exact block/loop/unpack/handler shadowing, recursion, cloned compile-time/default-method occurrences, nested generics, effects, argument markers, named results, reference returns, closure values, and method `self`; escape is rejected. The removed `unified {...}` spelling remains a documented Mojito-only compatibility extension. |
| Functions | Escaping closures | Excluded | Current Mojo does not support closures that outlive their enclosing scope; this is not a parity target. |
| Types | Scalars, strings, nominal collections, SIMD and slices | Run | Public `List`, `Set`, `Dict`, `Range`, and heterogeneous `Tuple` are self-hosted nominal structs. Their supported indexing, sizing, and containment use ordinary checked methods; borrowed List/Set/Dict/Range iteration and owned List iteration use selected nominal iterator methods. Public Tuple has no runtime iteration contract and never falls through to the private runtime-pack iterator path. Concrete List/Set/Dict-place borrowed iteration retains an origin-preserving owner loan; List alone additionally supports the checked `for ref` element bridge. Dict lookup refreshes its exact `value` owned-interior generation without invalidating the sibling `element` generation retained by key iteration. HashSet deletion and bucket-replacing `add` are available only for `ImplicitlyDeletable` elements. The bundled owned protocol uses current Mojo's monomorphic `IteratorOwnedType`; the borrowed trait retains the legacy monomorphic `Iter` member pending the origin-parameterized protocol migration. An ordinary value read through a reference-returning subscript requires a `Copyable` referent and runs that referent's copy lifecycle; an explicit `ref` binding retains the alias and remains legal for linear referents. Consuming a projected Copyable field similarly runs its nested copy lifecycle. Slice syntax preserves omitted, negative, and strided bounds; selects `ContiguousSlice` or `StridedSlice`; exposes optional bounds and `indices()`; and dispatches checked mixed/variadic user `__getitem__` and `__setitem__`. Every method-dispatched nominal subscript uses ordinary checked method-selection semantics and retains a complete `MirSubscriptCall`: exact target, executable result, and raising type; receiver/argument conventions and caller places; capture effects; source-ordered compile-time value arguments; reference-result origin; and setter write-back. Call-less `Index` and `Slice` name an exact intrinsic dispatch family, so the VM never selects semantics from a runtime value; the narrow nominally typed `Slice.indices()` result explicitly uses the private Tuple-storage bridge. A reference-returning subscript is evaluated once, retains its owner loans in a hidden reference slot, and can be used directly as a chained receiver/place, through a reference-valued aggregate, or as a dynamic `mut`/`ref` actual. Mojito's reference-field extension peels the outer element-slot handle when indexing `List[ref T]`, so augmented writes and chained method calls reach the stored referent without replacing its handle. Setter selection distinguishes positional and keyword-only value shapes, validates the actual right-hand side, and preserves receiver/index/right-hand-side evaluation order; raising getters/setters and mutable alias conflicts follow ordinary call and loan rules. String result APIs remain CPU semantic/library work. Tuples include bare displays/destructuring, inferred or typed construction, compile-time indexing, length, membership, comparison, concatenation, reversal, pack round-tripping, and dependent-handler `consume_elements`. Tuple lifecycle markers are conditional on every element; a `deinit` transform implicitly copies an `ImplicitlyCopyable` tuple but requires `^` for move-only elements. Indexed transfer of a non-`ImplicitlyCopyable` public tuple element stays rejected; `consume_elements` is the legal consuming API. `Int` and `Scalar[DType.int]` are one checked type; SIMD is value-level, not machine-vector code generation. |
| Indexing | Competing setter value shapes | Extension | Mojito resolves a focused positional-only/keyword-only `__setitem__` overload pair from the assignment right-hand-side type. The pinned nightly rejects that pair, so portable code should avoid it; the executable divergence is tracked as `setter-overload-extension`. |
| Indexing | Projected reference results | Run | A field below a nominal reference-returning subscript extends the accessor's one-evaluation hidden handle; subsequent Pointer, SIMD, and private-storage indices retain their typed dynamic projection. Direct `ref` bindings, dynamic `mut`/`ref` actuals, and reference-return forwarding preserve the selected call, projected origin, and caller place instead of becoming raw nominal storage projections. The field projection is shared differential evidence; the focused Pointer projection is Mojito-only until the current allocation/dereference spelling lands, while SIMD/private-storage steps currently have lowering/verifier rather than separate differential coverage. |
| Indexing | Augmented nominal subscripts | Run | `receiver[arguments] OP= rhs` evaluates receiver/index sources once and retains call-local conversions, effects, places, and complete accessor contracts. A value getter runs after the RHS, then the operator and independently adapted positional/keyword setter; a getter-mutated index place is reloaded before that setter. A mutable-reference getter establishes the lvalue before the RHS and writes through it directly with no setter. For a user-struct element, the operator step dispatches the element's dedicated in-place dunder (`__iadd__`, …) through both paths — a value getter materializes the element into a mutable temporary and sends the mutated result through `__setitem__`, a mutable-reference getter applies it through the handle — while a native scalar element keeps the binary read-modify-write. |
| Types | Collection displays and comprehensions | Run | Homogeneous list, set, and dictionary displays plus nested/filtering CPU comprehensions infer their element types, preserve key-before-value and clause evaluation order, enforce hashing/ownership requirements, and lower to the nominal collection constructors plus ordinary `append`/`add`/`__setitem__` method calls. Comprehension `for` clauses share the statement loop's borrowed-source lowering: a named source — collection or user iterable — is reference-bound (borrowed, not copied) with its whole-place or interior `element` loan re-established on the distinct iterator-object slot, so the source stays usable after the comprehension and mutating it mid-comprehension is rejected; a borrowed temporary is retained in its own slot and destroyed exactly once, after the comprehension. There are no collection-construction MIR opcodes or VM-native public collection values. `Ty::ComptimeList`/`Value::ComptimeList` are restricted to CTFE; `Ty::Tuple`/`Value::Tuple` and `MakeTuple` are restricted to compiler-private heterogeneous pack storage. |
| Types | `std.utils.Variant` tagged unions | Run | Explicit type packs, construction, `isa[T]()`, compile-time `is_type_supported[T]()`, projection, `set[T](value)`, consuming `take[T]()`/`unsafe_take[T]()`, and ownership-returning `replace[Tin, Tout](value)`/`unsafe_replace` use explicit checked MIR. Unsupported arms reject statically, checked operations validate tags, and lifecycle/Hashable/Writable/Equatable availability is gated element-wise. `destroy_with`, representation writing, and full TypeList-driven library APIs remain standard-library work. |
| Types | Origin-carrying parameter reference types | Check | Named/place origins, semantic-only `Origin` parameters, and fixed/symbolic mutability declarations are checked. |
| Types | Origin-carrying return reference types | Run | Parameter/receiver projections, unions, call substitution, invalid-local escape rejection, and returned alias execution are implemented. |
| Structs | Fields, fieldwise/manual construction, methods, copy/move/drop | Run | Structs have value semantics, including checked consuming copies of projected Copyable fields. |
| Generics | Typed parameters, defaults, constraints, and packs | Run | Type and typed scalar/aggregate value parameters support positional/named binding, inference, dependent defaults, infer-only declarations, trailing `where` predicates, type equality, and heterogeneous compile-time packs including `conforms_to(Ts.values, Trait)`; origin parameters are semantic facts and may appear before or after packs without shifting ordinary specialization arguments. |
| Generics | Variadic-generic structs (`struct S[*Ts: Bound]`) | Run | Compile-time elaboration specializes each explicit instantiation into a concrete struct (mirroring pack functions; the template is dropped): pack-typed members expand to the concrete element list, and `s.storage[i]` has the exact per-index element type at a compile-time-constant index. Specializations copy/move/drop as ordinary structs, and a pack constructor (`def __init__(out self, var *args: *Ts)`) checks each argument against its per-index element type with exact arity. Current Mojo's dependent accessor `def __getitem_param__[i: Int](self) -> Ts[i]` unrolls into per-element concrete accessors at specialization, so an ordinary value read `s[k]` has the exact element type and dispatches the checker-resolved accessor; an explicit `ref alias = s[k]` retains the returned handle. The earlier `__getitem__` spelling remains a compatibility fallback. General `__getitem_param__` methods receive the source index as a checked value parameter. Runtime-varying and out-of-range dependent pack indexing remain rejected. Public `std.collections.tuple.Tuple[*Ts]` uses this machinery and a private `__RuntimeTuple[*Ts]` field; exact generic callable elements cross generated declarations through opaque compiler-only ids backed by checker-seeded semantic types, so callable defaults, generic declarations, captures, and effects are not reconstructed from a lossy source spelling. Its `consume_elements` handler type indexes `Ts` by the handler's compile-time index. A bound-violating struct element is rejected by conformance verification, while a def-pack violation is diagnosed at the requesting call. |
| Metaprogramming | Unified `reflect[T]` and declaration selection | Check | Struct facts, named field indexes/types, dependent reflected types, and declaration-producing `comptime` branches elaborate before checking. Current `.field[name]` and `.field_at[index]` return chainable handles whose selected type is `.T`; the removed `field_type` spelling is rejected. ABI byte offsets belong to native backends. |
| Traits | Requirements, nominal conformance, monomorphic associated comptime facts | Run | Includes the protocols exercised by the self-hosted library. A monomorphic associated member declaration/projection carries a name; a parameterized member additionally retains its parameter list (see the parameterized row). A concrete `__next__ -> ref[o] T` may satisfy an abstract `__next__ -> T` only for an identical `Copyable` referent; abstract dispatch retains an explicit read/copy adapter while concrete calls retain their exact ABI. |
| Traits | Parameterized associated comptime types | Run | Trait and struct associated members retain type, value, and origin parameter lists (with the `//` infer-only boundary), as in `comptime IteratorType[iterable_mut: Bool, //, iterable_origin: Origin[mut=iterable_mut]]: Iterator`. A parameterized application such as `Self.IteratorType[origin_of(self)]` is validated against the declared explicit (post-`//`) parameter arity, and the checked `Ty::Assoc` carries the application's arguments (type, value, and origin, the last first-class in `TyArg` and erased from the runtime ABI like a pointer origin). When a conforming struct instantiates the member, the application resolves concretely by substituting those arguments into the member's lowered template: a type-parameterized member (`C.Wrap[T]` → `List[T]`) resolves through checked declarations, specialization, HIR, typed MIR, verification, and the register VM. An `origin_of(self)` origin argument resolves too: a trait method's abstract `Self.IteratorType[origin_of(self)]` lowers its receiver origin to a symbolic self-origin (erased at runtime), so a conforming struct's origin-parameterized associated member resolves concretely and conformance succeeds. A conformer may also spell the application directly as its own return type (`def make(ref self) -> Self.IteratorType[origin_of(self)]`): with the concrete struct substituted for `Self`, the indexed application resolves through the struct's member. Forwarding a value parameter into another parameterized struct (a pre-existing generic gap) and a generic free function returning `C.IteratorType[origin_of(c)]` (a declaration-time value-parameter-origin gap) remain later iteration work. |
| Traits | Refinement and default method bodies | Run | Requirements/capabilities inherit; defaults are statically materialized, explicit methods override, and ambiguity is rejected. |
| Traits | Monomorphic associated-type composition and conditional conformance | Run | Associated bounds merge across refinements; per-conformance `where` predicates are evaluated after type/value specialization. |
| Protocols | Indexer, Hasher, Writer, and Writable | Run | When an `Int` subscript contract is selected, a non-Int index is evaluated once and normalized through the checker-selected `__mlir_index__`; a direct overload accepting the source index type takes precedence. Hashing is incremental and caller-provided; display/repr and String fields stream through Writer with reflective defaults. |
| Protocols | Scalar operation traits | Run | Operators, comparisons, conversions, and rounding are typed through checked operation traits (`Addable`/`Subtractable`/…/`Comparable`/`Negatable`/`Intable`/…); the traits work as generic bounds, and user structs dispatch prefix operators and `Int`/`Float64`/`Bool`/`abs`/`round` through their dunders. Builtin scalars execute primitively behind the protocol, while literal-only evaluation stays exact until contextual materialization. |
| Overloading | Functions, methods, constructors | Run | Ranking minimizes conversions after applying the contextual `Int`/`Float64` defaults to unconstrained literals, then prefers fixed arity, shorter signatures, and concrete ties. Checked `@implicit` constructors participate and genuinely equivalent conversions remain ambiguous. |
| Comptime | Constants, `comptime if`, `comptime for`, type facts | Run | Elaborated before checking; numeric literal calculations retain arbitrary precision, runtime contexts materialize explicitly, and type/reflection handles erase. |
| Comptime | Unified `reflect[T]` queries | Run | Struct detection, field collections, named field indexes, chainable named/by-index field handles, dependent `.T` types, and declaration-producing compile-time selection run; ABI offsets are native-backend facts and field references use checked projections. |
| Comptime | Pure top-level CTFE through MIR/VM | Run | Fuel bounded; reflected compile-time branches may select and unroll declarations before name collection, while arbitrary string-to-AST generation remains unsupported. |
| Control flow | `if`, `while`, `for`, `break`, `continue`, ternary | Run | Concrete ordinary iteration, and consuming iteration for a type that supplies `__iter__(var self)`, use checker-selected nominal `__iter__`/`__next__` methods. A loop or comprehension target's binding convention — unadorned (immutable), `var`, or `ref` — is modeled independently of whether the source is borrowed or consumed: a `var` target moves an owned result into the loop variable or lifecycle-copies a yielded reference into owned storage (referent `ImplicitlyCopyable`), while an unadorned or `ref` target binds an owned result directly into per-iteration storage (a droppable `ImplicitlyDeletable` or `Copyable` element, dropped each iteration) or retains a yielded reference handle to read/write through the borrowed referent. The raw `__next__` result is retained in a compiler-owned slot and adapted to the target only on the yielded edge, so moves and copies never run on the `StopIteration` path; mutating an immutable target and a copying `var` over a non-`ImplicitlyCopyable` reference result are rejected. Borrowed sources lower uniformly — in statements and comprehensions — through a reference-bound retained-source slot and a distinct iterator-object slot, with whole-source versus interior borrowing expressed only as loan granularity. Bundled borrowed iteration covers List, Set, Dict, and Range; bundled owned iteration is currently List-specific. Current raising iterators terminate with typed `StopIteration`; `__len__` remains only for the legacy nonraising path. An abstract value-yielding iterator may dispatch to a concrete reference-yielding `__next__` for a `Copyable` element; the checked adapter reads and lifecycle-copies the referent. Concrete List-place `for ref` retains a live interior origin through a compiler bridge; generic origin-preserving borrowed sources and abstract `for ref` await the remaining ordered borrowed-iteration chain. `for var item in collection^` consumes the source, moves non-Copyable elements, drops permitted residual elements on early exit, and rejects early abandonment of linear residuals. The bundled List owned iterator currently requires `ImplicitlyDeletable` elements even for statically guaranteed full exhaustion; lifting that restriction is the separate **Owned iteration of linear elements** roadmap subtask. |
| Exceptions | `raise`, `try`/`except`/`else`/`finally` | Run | Direct, selected overload/method, indirect callable, trait-requirement, and bounded-dispatch effects are checked with exact typed error contracts; inferred `except` bindings and `Never` run. |
| Contexts | `with` statements | Run | Checked `__enter__`/`__exit__` calls execute around the body, including raising exits and manager mutation/write-back. |
| Modules | Source modules/packages, wildcard/selective, dotted/relative linking | Run | Every dotted prefix binds a namespace; ordinary directories can form namespace paths; package members require explicit import or `__init__.mojo` re-export; and a source package wins over a same-named source module. Compiled `.mojoc`/`.mojopkg` lookup remains Packaging, Artifacts, And Developer Tooling work. |
| Modules | Qualified `import module`, module/member aliases | Run | Aliased and full dotted calls, values, and types resolve without merging same-named declarations. |
| Ownership | `^` moves, partial moves, use-after-move analysis | Run | MIR dataflow owns these rules. |
| Borrowing | Local loans, interior origins, and origin-bearing cross-call references | Run | Frame/slot handles execute reborrows, free and receiver-projected returns, unions, captured indexes, and reference-valued aggregates. Direct, lifted indirect, method, callable-receiver, and handwritten-constructor ABIs retain positional and keyword caller places; synchronous `try` execution mirrors the caller's real frame identity, so projected or aggregate reference returns and mutations on both normal and raising paths have the same semantics as continuation-driven calls. Pointer-backed and self-hosted List projections remain executable through those handles. Bare `ref` parameters/receivers propagate caller mutability but cannot assume write permission; an explicit mutable origin is required to write. Named interior generations (`"element"`/`"value"`), including every member of a union return, let owner reads, overlapping element aliases, and direct List element writes coexist; structural mutation, nested-interior or whole-owner replacement through direct/reference/pointer access, mutable calls, Dict lookups, and Variant replacement invalidate matching old generations across branches, loops, and exact structured-exception channels. Direct `ref` struct fields are a documented Mojito extension (current Mojo spells reference storage through `Pointer`). A `ref[origin] T` field or binding whose origin is a struct/callable origin *parameter* may be returned from a method — directly (`self.value`) or by indexing/projecting through it (`self.src[i]` on a `ref[origin] List` field): the handle already names its borrowed region, so the return stays within the declared origin (an immutable origin yields a read-only borrow, a mutable origin a write-through handle) instead of escaping as a receiver-rooted place. The VM re-roots the returned handle at the borrowed storage so it survives the accessor frame. Reading a `ref[origin] <aggregate>` field's referent — subscripting it, taking its `len`, and similar — works under a `mut`/`ref self` receiver exactly as under `def self` (a borrowed receiver is a runtime alias, and the field load now dereferences to the referent rather than yielding its stored handle). A reference returned from a struct method and bound to a `ref` local keeps its source alive: the returned reference's struct origin parameter resolves to the origin the receiver's `ref[o]` field borrows, so the loan roots at the ultimate owner and it is not dropped while the reference is live (a `mut self` reference-yielding accessor reads and writes through end-to-end). Dereferencing an origin-bearing *pointer* field and returning it (`self.p[0]`, with `p: UnsafePointer[T, o]`) executes: the returned reference stays within the pointer's origin parameter, and the VM re-roots the handle at the single pointee — `UnsafePointer(to=v)` is a handle straight at `v` — forwarding the offset-0 index to it (an immutable origin reads, a mutable origin writes through the source). A `for` loop over a user-defined iterator whose `__next__` returns a reference into the borrowed source executes: the loop calls `__iter__`/`__next__` with the loop frame reachable, and a borrowed `__iter__(ref self)` receives a `ref self` handle, so a user iterator holding a `ref` into the loop frame resolves it and the yielded reference flows through the loop as a handle (owned-temporary source, dropped once after the loop; a named source binds the source slot to a genuine reference and is recorded as a whole-source shared loan on the iterator, so it is not copied, survives the loop without the `KeepAlive` hack, and mutating it during iteration is rejected as a loan conflict). The concrete `__next__` target, raising effect, and executable result convention cross the checked/HIR/MIR boundary together, so a reference yield is typed and verified as `Ty::Ref` rather than carried dynamically through a register typed as its referent. An abstract value-result `__next__` may retarget to that concrete reference ABI only for an identical `Copyable` referent; its explicit adapter reads from the identified returned frame and runs the copy lifecycle before producing the promised value. Static, untracked, and unsafe-any contracts lower explicitly, and `UnsafePointer(to=place)` attaches executable owner loans to pointers and pointer-storing aggregates. This is currently stricter than Mojo: Mojito rejects mutation of the designated owner while such a pointer remains live, whereas the pinned nightly permits it. |
| Unsafe pointers | Provenance, arithmetic, and lifetime | Run | Stable allocation identities, element offsets, allocation bounds, aligned allocation, dangling placeholders, real deallocation, and invalid/double-free diagnostics execute in the VM. Place-origin pointers execute as frame/slot handles; their checked origins reject offsets, arithmetic, comparison, `free()`, and escapes, and only the VM value erases provenance. Mojito still spells allocation as legacy `UnsafePointer[T].alloc[_aligned]` and indexed dereference as `pointer[0]`; current Mojo uses free `alloc[T](...)` plus `pointer[]`, tracked as an explicit API/syntax divergence. |
| Destruction | ASAP `__del__`, edge/try cleanup, aggregate teardown | Run | Liveness rewrites every owned MIR root with explicit drop glue. Reference-bearing aggregate generations retire their exact old owner on straight-line or CFG-edge rebinding, and transient reference-register provenance retains the selected owner through the consuming expression without extending it to scope exit. Nominal collection fields follow ordinary struct teardown; elements in the compiler-private heterogeneous pack carrier drop left-to-right, including moved variadic-pack and public-Tuple backing storage, exactly once. |
| Standard library | Self-hosted collections, algorithms, math, hashing | Run | Proof subset under `stdlib/`, not Mojo's full standard library. |
| Backend | Register VM | Run | Sole backend and runtime; direct calls use an explicit continuation-driven frame stack with monotonic frame identities. |
| Tooling | Textual MIR/VM assembly, parser, verifier, disassembler | No | Planned as a versioned Mojito-owned serialization and debugging format. |
| Backend | LLVM, MLIR, Pliron | No | Prioritized native backends after the textual MIR contract and VM semantics stabilize. LLVM is the primary target; MLIR and the Rust-native, MLIR-inspired [Pliron](https://github.com/pliron-org/pliron) (its LLVM dialect emits LLVM IR) are the MLIR-family options. `--backend=llvm\|mlir\|pliron` names are recognized seams that refuse construction until implemented. |
| Later backend | Cranelift, eBPF | No | Lower-priority options investigated after the LLVM/MLIR-family targets stabilize; not first-pass parity requirements. |
| Out of scope | GPU, concurrency/parallelism, distributed execution, Python interop | No | Intentionally excluded from the first Mojito parity target. |
