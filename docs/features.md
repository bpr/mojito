# Mojito Feature Matrix

This is the authoritative summary of language support. Update it in the same
change that alters a feature's status. [`grammar.md`](grammar.md) remains authoritative for
surface syntax; the tests remain authoritative for detailed behavior.
The machine-checkable comparison with pinned Mojo—including explicit divergences
and exclusions—lives in [`conformance/parity.tsv`](../conformance/parity.tsv).

Status meanings:

- **Run** — accepted by the production compiler and executed by the register VM.
- **Check** — represented and checked, but has no independent runtime behavior.
- **Parse** — preserved in the AST but deliberately rejected before execution.
- **No** — not reliably accepted even as syntax.

## Where Mojito Stands

Mojito has one production path: source is linked and elaborated, checked into
typed HIR, lowered to verified MIR, ownership- and liveness-analyzed, drop
elaborated, and executed by the register VM. The supported CPU surface includes
exact numeric literals, type/value/origin generics and heterogeneous packs,
scope-stable and lexical nested-pack specialization, refined and conditional
traits, recursively lifted typed closure environments, linear whole-pack
forwarding, generic-anonymous callable contracts, symbolic callable defaults,
residual callable specialization, origin-bearing references and current-model
unsafe pointers (the `unsafe_*` vocabulary, empty-`[]` dereference,
layout-based linear `std.memory` allocation with a tracked
`Allocation.unsafe_ptr()`, multi-element interior-domain origins carrying
the borrowed `Span`/`StringSpan` views — with current Mojo's strict slice
bounds, grapheme-cluster and Span element iteration, and the `@implicit`
List-to-Span conversion whose temporary refines its origin to the source —
and the experimental conservative `Origin._subtree` form, including
`Pointer(to=…)` through `ref` bindings),
collection-owned interior-origin generations, explicit lifecycle semantics, and
a self-hosted proof-subset standard library. Method-dispatched nominal
subscripts retain ordinary checked method selection in one complete verified
call contract, including effects, caller places, capture access, generic values,
and reference results; call-less index and slice operations name their exact
compiler-owned intrinsic family instead of asking the VM to infer one from a
runtime value. The narrow nominally typed `Slice.indices()` result still crosses
private Tuple storage through that explicit intrinsic bridge. Public
`List`, `Set`, `Dict`, heterogeneous `Tuple`, and current Mojo's private
Int/Scalar range family are nominal library structs; only compile-time lists
and the private heterogeneous runtime-pack carrier retain compiler-owned
aggregate representations.

## Support Matrix

| Area | Feature | Status | Boundary / notes |
|---|---|---:|---|
| Frontend | Indentation, continuations, comments, numeric/string literals, Mojo escapes | Run | Includes current radix/decimal/exponent separators, `Byte == UInt8`, raw and triple forms, and same-line or indented adjacent strings. Diagnostic parsing can report multiple statement-level errors. |
| Types | Exact numeric literals and scalar materialization | Run | Source `IntLiteral` values use arbitrary-precision integers; finite `FloatLiteral` values use exact rationals with negative-zero preservation. Literal-only arithmetic remains exact through compile-time evaluation. Checked HIR records the contextual boundary, MIR emits `MaterializeLiteral`, integer targets wrap to their width, and floating targets round once directly to binary32/binary64. |
| Frontend | T-strings | Run | Prefix order/case and raw/triple combinations are accepted; nested lexical structure is respected. A `t"…"` is a lazy value: interpolations require `Writable`, and the whole-program compiler desugars each occurrence into a construction of the self-hosted prelude `TString[*Ts]` struct whose interleaved pack captures literal segments and interpolation snapshots at creation, deferring formatting to Writable `write_to` (so `print`/`String(...)` consume it ordinarily; nesting works). Capture is by typed value snapshot — a non-Copyable place snapshots as a creation-time formatted string — where real Mojo captures immutable borrows (see `docs/mojo-nightly.md`). `TString[...]` type annotations are not spellable; the stage-composed seam and retained abstract generic bodies keep an output-identical eager-concatenation fallback. |
| Frontend | Walrus `:=` | Run | Evaluates once and introduces a function-scoped binding while producing the value. |
| Modules | File-scope declarations and runtime entry | Run | Runtime statements at file scope are rejected; execution begins in zero-argument `main()`. |
| Bindings | Typed/inferred `var` (required), late initialization, assignment | Run | `var` is the sole declaration form: a bare `x = e` (or `a, b = e`) targeting a name not in scope is rejected (`AssignToUndeclared`). `var` is **block-scoped** — a declaration inside a nested block is not visible after it. Reads require initialization on every reaching path (path joins retain a maybe-uninitialized state unless every reachable path assigns it); same-scope redeclaration and type changes are rejected. |
| Bindings | Field/index places, augmented assignment, tuple unpacking | Run | Place expressions evaluate indexes once. Augmented assignment on a user-defined value dispatches to its dedicated in-place dunder (`x += y` → `x.__iadd__(y)`, and `__isub__`/`__imul__`/`__itruediv__`/`__ifloordiv__`/`__imod__`/`__ipow__`) as a checked `mut self` method call for variables, projected fields, and nominal-subscript elements, mutating the receiver in place; Mojo does not fall back to `__add__`. A missing in-place dunder, an immutable receiver, and a mismatched right-hand side are rejected, and a raising in-place dunder participates in ordinary `try` handling. Native scalar targets keep the builtin read-modify-write. |
| Bindings | Local `ref name = place` | Run | Aliases variable/field/index storage; indexed places bind once; persistent CFG loans enforce exclusivity through last use. |
| Control flow | Loop `else`, `for ref`, context managers | Run | `break` bypasses loop `else`; reference iteration (`for ref`) runs the ordinary origin-parameterized `Iterable` protocol — the bundled List/Set iterators borrow their source and yield element references resolved to the source's mutability at the loop site, writing through element handles (including over temporaries); a `ref` target over a generic `Iterable` bound is rejected because the abstract contract yields values; `with` executes checked enter/exit calls, including raising exits. |
| Calls | Defaults, keywords, `/`, `*`, homogeneous `*args` | Run | One structural contract serves free, method, static-method, and hand-written constructor calls in the checker and VM. |
| Calls | Homogeneous `var **kwargs` and `**kwargs^` forwarding | Run | Current declaration syntax requires consuming `var **kwargs: T` and rejects bare `**kwargs: T`; function types retain the keyword-variadic role, and callable symbols distinguish it from an ordinary parameter of the same type. Free, generic, instance, static, bounded-trait, and indirect calls materialize an owned, insertion-ordered `StringDict[T]` (keys spelled `StringLiteral` — keyword names are compile-time strings; the VM ABI is unchanged by the nominal-String takeover). Forwarding consumes it through the shared binder, specialization, duplicate, origin, ownership, and effect checks. |
| Calls | Heterogeneous `*args: *ArgTypes` | Run | Per-element bound checking, an explicit checked runtime-pack ABI with private heterogeneous `Value::Tuple` storage, and compile-time `args.__len__()` iteration/indexing run for literal and directly constructed arguments. Before generating a specialization, the call-site conformance diagnostic identifies the one-based failing element, its concrete type, the pack, and the unsatisfied trait. A pre-check resolver assigns stable value/type binding identities, so pack spreading and type expansion respect nested definitions, lexical blocks, loops, comprehensions, sibling methods, and empty packs. Nested templates have scope-qualified identities, specialize independently at their lexical declaration, lift recursively at arbitrary depth, and preserve captures/defaults/keywords/named results. A complete forwarded pack follows the fully supplied fixed positional prefix and precedes a keyword/default tail; its private pack collector moves as one value without copying linear elements. Type and value packs may be interleaved with semantic-only `Origin`/`OriginSet` parameters; a pack consumes only its source-layout segment, so a named Origin suffix remains at the rewritten call. A second spread or explicit positional overflow after the spread is rejected, matching the pinned nightly. Specialization exposes the concrete type of each statically indexed pack element; ordinary tuple-valued homogeneous variadics remain nominal `List` collectors. |
| Calls | Generic callable constraints and callable-value parameters | Run | `F: def(T) -> T` is retained as a dependent checked constraint, makes `F` callable inside the generic body, and validates a monomorphic contract against one monomorphic function type or nominal callable struct. A contract with its own `def[...]` list instead accepts an alpha-equivalent generic function, retaining binder arity, bounds, conventions, effects, reference origins, and invocation defaults. Compatibility is directional: a nonraising/read-only implementation may satisfy a raising/mutable contract, while ownership-changing conventions and reference-origin contracts remain exact. An explicit environment qualifier on the right-hand side (`callback: def(...) thin` or `capturing[...]`) declares a compile-time callable-value parameter; `OriginSet`, `capturing[_]`, `capturing[origins]`, and the infer-only `//` marker are retained, and the supplied function or closure is reified into a hidden typed runtime local for indirect calls. Callable-value defaults are symbolic selected-function, earlier-parameter, or compile-time-conditional plans evaluated in declaration order. Comptime specialization bakes the scalar/type/pack values it inspects while retaining callable and Origin arguments on the residual signature and call site; `CtValue` deliberately has no function or closure variant, and arbitrary callable CTFE is not implied. |
| Calls | Callable capture-origin contracts | Run | Checked function types distinguish unqualified, `thin`, and `capturing` environments. Materialized closures carry a canonical concrete origin set with read/write access per captured owner; `OriginSet` parameters and inference placeholders remain symbolic until a concrete callable is supplied. These dependencies participate in substitution, nominal conformance, origin escape checking, checked HIR, typed MIR declarations, and direct, indirect, method, and nominal subscript capture effects, so persistent-loan analysis sees mutations performed by a directly called closure or a non-escaping callable argument. A capturing closure no longer binds to an unqualified `def(...)` value contract — the checker rejects it with a hint naming the `capturing[...]` spelling, matching current Mojo; comptime callable bounds (`F: def(...)`) still ground capturing values, as upstream accepts. A thin (non-capturing) callable satisfies every `capturing[...]` value contract — its capture set is empty, a subset of any allowed origin set — matching upstream's acceptance of plain functions for capturing funargs. |
| Calls | Method/generic argument-binding parity | Run | Includes ordinary-parameter write-back. |
| Calls | User-defined static methods | Run | Uses the same positional/default/keyword ABI without a receiver slot. |
| Calls | Callable expressions / first-class function values | Run | Non-capturing, generic, origin-specialized, and contextually selected overloaded functions can be stored, passed, and indirectly invoked with checked raising and capture effects plus reference returns. Explicit Origin arguments participate in direct overloaded and generic calls, combine with explicitly supplied ordinary generic arguments in function values, and select an overloaded function value when an expected `def(...)` type identifies one candidate; an uncontextualized overloaded value remains ambiguous. User structs are callable only when they nominally conform to a matching `def(...)` contract and implement `__call__`; callable generic parameters, environment constraints, `mut`/`ref` conventions, origin-bearing results, the receiver place, and the exact signature-qualified `__call__` target survive conformance and indirect lowering, including same-arity overload sets. Captured nested Origin specialization remains a documented Mojito extension over the pinned nightly. |
| Calls | Named `out` results | Run | A free function's single `out` parameter is a caller-transparent result slot and must be initialized before fallthrough or bare return. |
| Conventions | `imm`/legacy `read`, `var`, `mut`, `ref` parameters and `ref self` | Run | `imm` and its temporary compatibility synonym `read` share immutable-reference semantics. A bare aggregate variable passed to a read-convention or `mut`/`ref` parameter binds as a shallow place read — no argument-side `__copyinit__` runs, matching Mojo's borrow (consuming `var`/`deinit` passes still run the copy lifecycle; field-chain and reference-result actuals already read shallowly). Copyable immutable arguments overlapping a `mut`/`ref`/`^` access in the same call are materialized through the implicit copy that satisfies exclusivity; non-Copyable aliases remain errors. |
| Conventions | `out self`, named `out` results, `deinit self` | Run | Lifecycle receivers and a single free-function named result are supported. |
| Lifecycle | `Deinitable`/`__deinit__`, unified copy/move initialization, and `@implicit` constructors | Run | Ordinary values are implicitly deinitable; an explicitly false conditional conformance makes a type linear. The upstream-deprecated `ImplicitlyDeletable`/`__del__` spellings are accepted and normalized to the canonical vocabulary at parse time (removed when upstream removes them). A declared conditional `Movable` conformance is effective: `Movable where False` rejects `^` transfers, `var` parameters/receivers, and move/copy captures, while `deinit` consumption (destructors, named destructors) stays legal and Copyable pass-by-value is unaffected. A bare `move:` initializer parameter is rejected with a migration diagnostic naming the `deinit move: Self` spelling. `Copyable` carries current Mojo's non-overridable default `copy()`: elaboration synthesizes `def copy(self) -> Self` on every struct declaring `Copyable`/`ImplicitlyCopyable` that does not spell its own, delegating to a declared `__init__(out self, *, copy: Self)` (run exactly once per copy — the construction reads its source as a retained borrowed place) or falling back to the fieldwise copy lifecycle, with a conditional conformance's predicate carried over as the method's `where` clause; a `T: Copyable`-bounded parameter resolves the same `copy() -> Self` contract. |
| Lifecycle | `@explicit_destroy` | Run | The required string argument customizes linearity diagnostics but does not itself make a type linear. Named `deinit self` methods discharge path-sensitive obligations. Abandonment, overwrite, partial/double/conditional destruction are rejected; raising destruction preserves the value for an `except` fallback and automatic `DropVar` destruction is suppressed. |
| Functions | Recursion and conservative return checking | Run | Sibling forward references and mutual recursion are rejected. The future-syntax words `class`, `del`, `match`, and `yield` remain lexer-level identifiers, but declaration checking rejects them as free or nested function names; they remain legal as ordinary variables/parameters, and method names such as `match` remain valid. |
| Functions | Non-escaping closures | Run | Current capture lists use `{imm name}`, `{mut name}`, `{ref name}`, `{var name}`, move/default forms, or `{}`. Reference captures retain frame/slot handles without imposing a declaration-to-call loan, so `imm` observes intervening outer updates; `var` copies at declaration, and move capture transfers at declaration. Checked captures retain exact owner identity, storage type, and convention even when unused. Lexical declarations lift recursively at arbitrary depth while preserving materialized sibling snapshots, ancestor forwarding, exact block/loop/unpack/handler shadowing, recursion, cloned compile-time/default-method occurrences, nested generics, effects, argument markers, named results, reference returns, closure values, and method `self`; escape is rejected. `def(...)`-typed struct fields and collection elements are rejected with a contextual error, matching current Mojo (which treats a bare `def(...)` in those type positions as a trait): callable values are limited to parameters and `def(...) thin` local bindings — bare and `capturing` local annotations reject like fields and elements, and a generic function does not contextually specialize into a stored callable value. The removed `unified {...}` spelling is rejected with a contextual parse error. |
| Functions | Lambda expressions | Run | `lambda [[params]] [(args)] [effects] [{captures}] [-> T]: expr` — the parser synthesizes a hidden nested `def` whose body is `return <expr>`, so checking, capture analysis, closure lifting, and indirect calls reuse the nested-def pipeline, and the closure materializes at the expression's evaluation point (`{var}` snapshots once per loop iteration; an immediately invoked owned-capture lambda gets a synthetic stable slot). An omitted return type is fixed to `None`, never inferred, with a contextual diagnostic naming the rule. An omitted capture list imm-captures free variables — thin when none are captured — while explicit `{}` captures nothing ("could not infer capture convention") and an explicit capture-all convention (`{imm}`) or a lambda-owned parameter list forces a closure even with zero captures. Arguments must be parenthesized and typed (contextual parse diagnostic); conventions, variadics, and `raises` parse as on `def`s. Generic lambdas invoke inline (`(lambda [N: Int](x: Int) {} -> Int: x + N)[5](3)`), bind callable-bound generic type parameters as runtime arguments, and compile-time unrolling clones a lambda per iteration with the unroll variable substituted (hidden names uniquify at final-tree rekeying); partial parameter application into a stored value remains unsupported (value-base brackets dispatch runtime element calls, and a stored callable value takes no compile-time parameters). Storing a lambda in a local requires the same explicit `def(...)`/`capturing[...]` annotation as any function value (upstream infers un-annotated `var f = lambda …`), calling a lambda in a compile-time initializer is rejected ("not a compile-time value"), and lambdas in parameter defaults are rejected contextually. |
| Functions | Function-type `where` clauses | Run | A `thin` function type with its own `def[...]` parameters carries trailing `where` clauses (`F: def[w: Int](Int) thin -> None where (w > 0, "msg")`): clauses lower onto the anonymous contract's parameter declarations with alpha-renamed binder identity, explicit specializations through the parameter evaluate them, and the binding rule is directional — a constrained function needs the contract to declare the matching clause, while unconstrained-into-constrained is allowed. Binder-less clauses and `comptime` function-type aliases are recorded mojo-only gaps. |
| Expressions | Contextual member references | Run | A leading-dot chain (`var c: Color = .red()`, `takes_color(.of(7))`, `[.red(), .of(3)]` under a `List[Color]` annotation, `return .red()`) resolves its base against the expected type: the parser builds the chain over the compiler-internal `$contextual` sentinel, the checker re-checks the spelled form with spans preserved, and HIR substitutes the base name. Without a contextual type the form rejects. Recorded gaps: bare `.member` comptime value members, parametric statics, non-struct and generic expected types, type positions. |
| Functions | Escaping closures | Excluded | Current Mojo does not support closures that outlive their enclosing scope; this is not a parity target. |
| Types | Scalars, strings, nominal collections, SIMD and slices | Run | Public `List`, `Set`, `Dict`, heterogeneous `Tuple`, and fixed-size `Array[T, length]` are self-hosted nominal structs (`List[T: AnyType]` matches the head's relaxed bound: the moving APIs — `append`/`insert`/`pop`/`grow`/`reverse`/`remove`/`__setitem__`/literal construction/owned iteration — state their own `Movable` requirement, so an empty `List` of a pinned element type is legal; growth 2026-08: capacity/length-fill constructors, `reserve`/`resize`/`shrink`/`swap_elements`/`capacity`, `unsafe_get`/`unsafe_set`, equality, `__bool__`, `+`/`+=` concatenation and `*`/`*=` repetition, Optional-returning `try_index`, raising `index`, and upstream's consuming `extend(var other)`). `Dict[K: Hashable & Equatable & Copyable & Movable, V]` is hash-bucketed over dense insertion-ordered entries (doubling at load factor one) with pop/LIFO popitem/setdefault/update/clear/`|` merge/order-insensitive equality/`__bool__`/capacity construction, and `keys`/`values`/`items` return self-iterable, non-indexable borrowing views; `Set[T: Hashable & Equatable & Copyable & Movable]` adds remove/discard/LIFO pop/clear/update, the union/intersection/difference/symmetric_difference families with `&`/`|`/`-`/`^` operators and subset/superset comparisons, and read-only element yields, and `range(...)` returns current Mojo's private range family — `_ZeroStartingRange`/`_SequentialRange`/`_StridedRange[dtype: DType = DType.int]`, each its own borrowed typed-raising iterator over `Scalar[dtype]` elements, with upstream's construction rules (a negative zero-start end clamps empty, the two-argument form never counts down, a zero step canonicalizes to the empty range). Int arguments select the stdlib overloads; scalar arguments infer the dtype through checker-selected specialization (upstream's infer-only `range[dtype: DType, //]` overloads have no explicit spelling), rejecting mixed dtypes, Bool, and float dtypes (1/2-argument floats need a step; float strided ranges are a recorded gap). Length and Int subscripts run; `reversed()`/`bounds()`/`__has_next__`, containment, formatting, non-Int `Indexer` arguments, and `comptime for` over scalar ranges are recorded subset gaps. `Array` (prelude-exported, `UnsafePointer`-backed) declares conditional `Copyable`/`Movable`/`Deinitable`/`Equatable`/lexicographic `Comparable`/`Iterable`/`IterableOwned`/`Writable` conformances over its `T: AnyType` element and an `Int` value parameter; it supports keyword `fill`/`copy:`/`deinit move:` construction and the checker-driven variadic literal constructor, by-reference `__getitem__` (no `__setitem__`, matching upstream Array), `__len__`/`__eq__`/`__ne__`/`__contains__`, and borrowed plus owned iteration, and is neither `ImplicitlyCopyable` nor `Defaultable` (upstream's conditional `Defaultable` needs generic `Self.T()` construction, and consuming `concat`/`repeat` need dependent result lengths — recorded mojo-only gaps) (`Hashable`, `unsafe_ptr`, `__getitem_param__`, `uninitialized:` construction, and `deinit_with` are not yet provided). Their supported indexing, sizing, and containment use ordinary checked methods; borrowed List/Set/Dict/range-family iteration and owned List/Set iteration use selected nominal iterator methods (`Optional` is prelude-exported like upstream; `Set` stays prelude-visible — upstream requires an explicit import for the name, a recorded divergence — while set displays work without the name on both sides). Public Tuple has no runtime iteration contract and never falls through to the private runtime-pack iterator path. Concrete List/Set/Dict-place borrowed iteration retains an origin-preserving owner loan, re-established on a reference-yielding loop binding so an invalidation names the user's variable; List and Set support `for ref` element write-through via the generic protocol. Dict lookup refreshes its exact `value` owned-interior generation without invalidating the sibling `element` generation retained by key iteration. The bundled owned protocol uses current Mojo's monomorphic `IteratorOwnedType`; the borrowed trait uses current Mojo's origin-parameterized `IteratorType[iterable_mut: Bool, //, iterable_origin: Origin[mut=iterable_mut]]` with `__iter__(ref self) -> Self.IteratorType[origin_of(self)]`, while the bundled member templates stay origin-erased: every bundled borrowed iterator (`_ListIter` for List/Set, `_SpanIter` for Span, `_DictKeyIter` for Dict/StringDict) carries its origin as an erased struct parameter, borrows its source through a `ref` field, and declares its yielded reference as `ref[iterable_origin._get_owned_interior["element"]]` — the checker derives each source loan's granularity from that declared projection instead of a collection-name whitelist, so any conformer iterating at interior granularity gets the same protection. Any `mut self` mapping method during iteration lazily invalidates the iteration generation (mapping mutation during iteration is a rejected error, matching Mojo's documented contract), while `d[key]` value reads refresh only the sibling `value` generation; `keys`/`values`/`items` views borrow the live entries (source mutation while a view lives is rejected; value/entry yields are read-only, a conservative subset of upstream's mut-following value references), and `take_items` drains lazily through a mutably borrowing iterator. An ordinary value read through a reference-returning subscript requires a `Copyable` referent and runs that referent's copy lifecycle; an explicit `ref` binding retains the alias and remains legal for linear referents. Consuming a projected Copyable field similarly runs its nested copy lifecycle. Slice syntax preserves omitted, negative, and strided bounds; selects `ContiguousSlice` or `StridedSlice`; exposes optional bounds and `indices()`; and dispatches checked mixed/variadic user `__getitem__` and `__setitem__`. List's contiguous slice overload is strict (current Mojo bounds): a negative, out-of-range, or reversed bound aborts through the uncatchable `os.abort` trap instead of normalizing (with the audited head's interpolated start/end/reversed messages), while strided List slicing keeps `StridedSlice.indices()` normalization and the copied result; a `Slice`-typed descriptor value still dispatches to the normalizing overload (recorded residue), and user-defined slice descriptors keep their own semantics. `Span(list)` (prelude-exported, `std.span`) is a borrowed contiguous view — a multi-element origin-bearing pointer plus length whose construction lends the List's place (shared loan) so structural mutation conflicts while any view lives; element access is a reference result (write-through works on a mutable source), contiguous sub-slices are strict sub-views of the same storage, and strided Span slicing selects no overload. Span's constructor is `@implicit` (current Mojo's temporary-origin inference): a `List` passes directly wherever a `Span` is expected — free-call and method arguments, annotated bindings, and returns — the conversion result borrowing the source list exactly like the explicit construction (a hidden retained slot keeps the source alive across the consuming expression, structural mutation while the converted view lives conflicts, and returning a view of a frame-local list rejects with the same `escapes storage` family). A bare list literal does not convert (it types as fixed-size `Array`, a recorded subset gap — bind it to a `List` first). Span is `Iterable where conforms_to(T, Copyable)` through the same origin-parameterized protocol as List: `for x in span` reads element values, `for ref x` writes through to the underlying List, a sub-slice view iterates its own window, and structural mutation of the source during iteration conflicts with the live view (`_SpanIter` borrows the span through a `ref` field and yields `ref[iterable_origin._get_owned_interior["element"]]` references; reading the source between a mutable span loop and a later use of the span keeps the recorded order-sensitive over-rejection). `List.unsafe_ptr()` mints the underlying interior-generation pointer directly (offsets legal, staled by mutation); `Pointer(to=x)` stays single-place, and `unsafe_origin_cast` rebinds pointer provenance without upgrading immutable capability. A named bracket argument over a lowercase (value) base is a keyword subscript (`x[byte=i]`) dispatching keyword-only `__getitem__` overloads through ordinary structural call binding (keyword subscript assignment is rejected; named brackets over a type name remain compile-time parameter application), and keyword-only parameter names are part of overload identity — two same-arity overloads may differ only by their keyword selectors. A named bracket argument whose value is a slice (`x[byte=a:b]`, omitted bounds preserved, explicit second colon selecting `StridedSlice`) is a keyword slice binding a keyword-only slice-descriptor parameter through the same structural call binding, read-only like every keyword subscript. Every method-dispatched nominal subscript uses ordinary checked method-selection semantics and retains a complete `MirSubscriptCall`: exact target, executable result, and raising type; receiver/argument conventions and caller places; capture effects; source-ordered compile-time value arguments; reference-result origin; and setter write-back. Call-less `Index` and `Slice` name an exact intrinsic dispatch family, so the VM never selects semantics from a runtime value; the narrow nominally typed `Slice.indices()` result explicitly uses the private Tuple-storage bridge. A reference-returning subscript is evaluated once, retains its owner loans in a hidden reference slot, and can be used directly as a chained receiver/place, through a reference-valued aggregate, or as a dynamic `mut`/`ref` actual. Mojito's reference-field extension peels the outer element-slot handle when indexing `List[ref T]`, so augmented writes and chained method calls reach the stored referent without replacing its handle. A store into storage that outlives the frame — a field of `self` or a parameter-rooted place — rejects a frame-locally rooted loan (including rebinding a `ref` field to a local place) with the same `escapes storage` family as the return boundary; parameter-rooted loans store outward freely. Assignment through a `ref`-typed field writes through the stored handle into the referent (the store twin of the read path's second dereference), values that outlive a frame re-root their interior reference handles, and a bare struct name as an explicit compile-time argument (`List[RefBox]()`) is erased from runtime argument emission like an origin argument. Setter selection distinguishes positional and keyword-only value shapes, validates the actual right-hand side, and preserves receiver/index/right-hand-side evaluation order; raising getters/setters and mutable alias conflicts follow ordinary call and loan rules. Plain subscript assignment on a receiver with no `__setitem__` writes through a mutable-reference-returning `__getitem__` (upstream Array's contract), finishing with a direct reference write; an immutable receiver or immutable-reference getter rejects, and slice/multi-index assignment keeps the setter requirement. The self-hosted nominal `String` (a UTF-8 byte buffer over `UnsafePointer[Byte]`, prelude-exported, with the 2026-08 stabilizations: the bare `String()` empty constructor, pre-sized `String(capacity_bytes=…)`, and `reserve_bytes`) is the meaning of every source `String` annotation — the type-level `StringLiteral`/`String` split is complete. Overload symbols keep the stable `String` spelling for both types, so overloads differing only in that pair are rejected as redeclarations. Named interior generations (`"element"`/`"value"`), including every member of a union return, let owner reads, overlapping element aliases, and direct List element writes coexist; structural mutation, nested-interior or whole-owner replacement through direct/reference/pointer access, mutable calls, Dict lookups, and Variant replacement invalidate matching old generations across branches, loops, and exact structured-exception channels. Consuming an aggregate that carries an interior-origin loan requires the origin to still be live (current Mojo's rule): moving a stale view or passing it to a named explicit destructor rejects as a use of the invalidated interior reference, while a scope-end implicit drop of a stale view stays legal. The dual holds for owners: a whole-variable move (`dealloc(a^)`, a `var` argument, a rebind) invalidates every interior generation rooted at the moved variable, so a tracked pointer or view into it rejects on its next use. Direct `ref` struct fields are a documented Mojito extension (current Mojo spells reference storage through `Pointer`). A `ref[origin] T` field or binding whose origin is a struct/callable origin *parameter* may be returned from a method — directly (`self.value`) or by indexing/projecting through it (`self.src[i]` on a `ref[origin] List` field): the handle already names its borrowed region, so the return stays within the declared origin (an immutable origin yields a read-only borrow, a mutable origin a write-through handle) instead of escaping as a receiver-rooted place. The VM re-roots the returned handle at the borrowed storage so it survives the accessor frame. Reading a `ref[origin] <aggregate>` field's referent — subscripting it, taking its `len`, and similar — works under a `mut`/`ref self` receiver exactly as under `def self` (a borrowed receiver is a runtime alias, and the field load now dereferences to the referent rather than yielding its stored handle). A reference returned from a struct method and bound to a `ref` local keeps its source alive: the returned reference's struct origin parameter resolves to the origin the receiver's `ref[o]` field borrows, so the loan roots at the ultimate owner and it is not dropped while the reference is live (a `mut self` reference-yielding accessor reads and writes through end-to-end). Dereferencing an origin-bearing *pointer* field and returning it (`self.p[0]`, with `p: UnsafePointer[T, o]`) executes: the returned reference stays within the pointer's origin parameter, and the VM re-roots the handle at the single pointee — `UnsafePointer(to=v)` is a handle straight at `v` — forwarding the offset-0 index to it (an immutable origin reads, a mutable origin writes through the source). A `for` loop over a user-defined iterator whose `__next__` returns a reference into the borrowed source executes: the loop calls `__iter__`/`__next__` with the loop frame reachable, and a borrowed `__iter__(ref self)` receives a `ref self` handle, so a user iterator holding a `ref` into the loop frame resolves it and the yielded reference flows through the loop as a handle (owned-temporary source, dropped once after the loop; a named source binds the source slot to a genuine reference and is recorded as a whole-source shared loan on the iterator, so it is not copied, survives the loop without the `KeepAlive` hack, and mutating it during iteration is rejected as a loan conflict). The concrete `__next__` target, raising effect, and executable result convention cross the checked/HIR/MIR boundary together, so a reference yield is typed and verified as `Ty::Ref` rather than carried dynamically through a register typed as its referent. An abstract value-result `__next__` may retarget to that concrete reference ABI only for an identical `Copyable` referent; its explicit adapter reads from the identified returned frame and runs the copy lifecycle before producing the promised value. Static, untracked, and unsafe-any contracts lower explicitly, and `UnsafePointer(to=place)` attaches executable owner loans to pointers and pointer-storing aggregates. This is currently stricter than Mojo: Mojito rejects mutation of the designated owner while such a pointer remains live, whereas the pinned nightly permits it. |
