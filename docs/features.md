# Mojito Feature Matrix

This is the authoritative summary of language support. Update it in the same
change that alters a feature's status. [`grammar.md`](grammar.md) remains authoritative for
surface syntax; the tests remain authoritative for detailed behavior.
The machine-checkable comparison with pinned Mojo—including explicit divergences
and exclusions—lives in [`conformance/parity.tsv`](../conformance/parity.tsv).

Status meanings:

- **Run** — accepted by the production compiler and executed by the register VM.
- **Check** — represented and checked, but has no independent runtime behavior.
- **Parse** — preserved in the AST but deliberately rejected before execution.
- **No** — not reliably accepted even as syntax.

## Where Mojito Stands

Mojito has one production path: source is linked and elaborated, checked into
typed HIR, lowered to verified MIR, ownership- and liveness-analyzed, drop
elaborated, and executed by the register VM. The supported CPU surface includes
exact numeric literals, type/value/origin generics and heterogeneous packs,
scope-stable and lexical nested-pack specialization, refined and conditional
traits, recursively lifted typed closure environments, linear whole-pack
forwarding, generic-anonymous callable contracts, symbolic callable defaults,
residual callable specialization, origin-bearing references and current-model
unsafe pointers (the `unsafe_*` vocabulary, empty-`[]` dereference,
layout-based linear `std.memory` allocation with a tracked
`Allocation.unsafe_ptr()`, multi-element interior-domain origins carrying
the borrowed `Span`/`StringSpan` views — with current Mojo's strict slice
bounds, grapheme-cluster and Span element iteration, and the `@implicit`
List-to-Span conversion whose temporary refines its origin to the source —
and the experimental conservative `Origin._subtree` form, including
`Pointer(to=…)` through `ref` bindings),
collection-owned interior-origin generations, explicit lifecycle semantics, and
a self-hosted proof-subset standard library. Method-dispatched nominal
subscripts retain ordinary checked method selection in one complete verified
call contract, including effects, caller places, capture access, generic values,
and reference results; call-less index and slice operations name their exact
compiler-owned intrinsic family instead of asking the VM to infer one from a
runtime value. The narrow nominally typed `Slice.indices()` result still crosses
private Tuple storage through that explicit intrinsic bridge. Public
`List`, `Set`, `Dict`, heterogeneous `Tuple`, and current Mojo's private
Int/Scalar range family are nominal library structs; only compile-time lists
and the private heterogeneous runtime-pack carrier retain compiler-owned
aggregate representations.

## Support Matrix

| Area | Feature | Status | Boundary / notes |
|---|---|---:|---|
| Frontend | Indentation, continuations, comments, numeric/string literals, Mojo escapes | Run | Includes current radix/decimal/exponent separators, `Byte == UInt8`, raw and triple forms, and same-line or indented adjacent strings. Diagnostic parsing can report multiple statement-level errors. |
| Types | Exact numeric literals and scalar materialization | Run | Source `IntLiteral` values use arbitrary-precision integers; finite `FloatLiteral` values use exact rationals with negative-zero preservation. Literal-only arithmetic remains exact through compile-time evaluation. Checked HIR records the contextual boundary, MIR emits `MaterializeLiteral`, integer targets wrap to their width, and floating targets round once directly to binary32/binary64. A literal argument to a generic constructor materializes to the solved parameter type on every constructor path (explicit or inferred application, fieldwise, overloaded), and a literal against an explicitly bound parameter widens to the binding (`Pair[Float64](0.5, 1)`). |
| Types | Target-layout size queries | Run | `size_of[T]()` returns an `Int` byte count from the shared native `LayoutCx`, including aggregate padding. Parametric MIR keeps the query over the checked type (`MirInstr::SizeOf`, over `T` in a template-served `def`); the elaborator answers it under the compilation's native target — the host for a VM run, `--target` for a native compile — once the instance's types are concrete, so concrete MIR holds the constant and both backends agree by construction. Layout is asked only of a concrete type: a symbolic one is `LayoutError::Symbolic`. A module constant built by a layout query (`comptime S = size_of[Pair]()`) and a direct `size_of[T]()` in a SIMD width retain the query through checking; type substitution replaces its operand, and the elaborator resolves its size. Generic vector parameters, returns, and constructions at that width run (`assets/ok/comptime_layout_constant.mojo`). |
| Frontend | T-strings | Run | Prefix order/case and raw/triple combinations are accepted; nested lexical structure is respected. A `t"…"` is a lazy value: interpolations require `Writable`, and the whole-program compiler desugars each occurrence into a construction of the self-hosted prelude `TString[*Ts]` struct whose interleaved pack captures literal segments and interpolation snapshots at creation, deferring formatting to Writable `write_to` (so `print`/`String(...)` consume it ordinarily; nesting works). Capture is by typed value snapshot — a non-Copyable place snapshots as a creation-time formatted string — where real Mojo captures immutable borrows (see `docs/mojo-nightly.md`). `TString[...]` type annotations are not spellable; the stage-composed seam and retained abstract generic bodies keep an output-identical eager-concatenation fallback. |
| Frontend | Walrus `:=` | Run | Evaluates once, assigns to a name already in scope, and produces the value. A walrus never introduces a binding: an unknown target is `AssignToUndeclared`, as the pinned Mojo reports "use of unknown declaration". |
| Modules | File-scope declarations and runtime entry | Run | Runtime statements at file scope are rejected; execution begins in zero-argument `main()`. |
| Bindings | Typed/inferred `var` (required), late initialization, assignment | Run | `var` is the sole declaration form: a bare `x = e` (or `a, b = e`) targeting a name not in scope is rejected (`AssignToUndeclared`). `var` is **block-scoped** — a declaration inside a nested block is not visible after it. Reads require initialization on every reaching path (path joins retain a maybe-uninitialized state unless every reachable path assigns it); same-scope redeclaration and type changes are rejected. |
| Bindings | Field/index places, augmented assignment, tuple unpacking | Run | Place expressions evaluate indexes once. Augmented assignment on a user-defined value dispatches to its dedicated in-place dunder (`x += y` → `x.__iadd__(y)`, plus `__isub__`/`__imul__`/`__itruediv__`/`__ifloordiv__`/`__imod__`/`__ipow__` and bitwise `__iand__`/`__ior__`/`__ixor__`) as a checked `mut self` method call for variables, projected fields, and nominal-subscript elements, mutating the receiver in place; a value of a bare type parameter whose bound requires the in-place dunder (`T: Accum` declaring `__iadd__`) dispatches through the bound the same way; Mojo does not fall back to the ordinary binary dunder. A missing in-place dunder, an immutable receiver, and a mismatched right-hand side are rejected, and a raising in-place dunder participates in ordinary `try` handling. A collection element converts to a borrowing view operand in place (`out += parts[i]` over a `String` collector, `t += xs[0]` over a `List[String]`, `width(xs[1])` at a `StringSpan` parameter): the view binds the element's place and keeps the container alive until the call returns, and an operand overlapping the subscript target (`xs[1] += xs[0]`) is rejected as aliasing, as the pin does (`assets/ok/string_element_view_conversion.mojo`, `assets/type_error/subscript_inplace_operand_aliasing.mojo`). A reference result converts the same way (`width(p.name_ref())`, `out += pick(t)`), its view binding the referent the accessor returns, and a binding annotated with the view type (`var v: StringSpan[origin_of(p.name)] = p.name_ref()`, `= xs[1]`) keeps that source's owner alive as long as the binding lives (`assets/ok/reference_result_view_conversion.mojo`). Native Int/UInt targets keep the builtin read-modify-write, including `&=`/`|=`/`^=`. Unpacking a tuple place (`var s, n = t`, `a, b = t`) copies each element into its target, so a `String` element is owned by the target and by the tuple independently; an element that is not `ImplicitlyCopyable` is rejected at a named target, and `_` reads nothing (`assets/ok/tuple_unpack_place_copies.mojo`, `assets/type_error/tuple_unpack_place_element_not_implicitly_copyable.mojo`). |
| Bindings | Local `ref name = place` | Run | Aliases variable/field/index storage; indexed places bind once; persistent CFG loans enforce exclusivity through last use. |
| Control flow | Loop `else`, `for ref`, context managers | Run | `break` bypasses loop `else`; reference iteration (`for ref`) runs the ordinary origin-parameterized `Iterable` protocol — the bundled List/Set iterators borrow their source and yield element references resolved to the source's mutability at the loop site, writing through element handles (including over temporaries); a `ref` target over a generic `Iterable` bound is rejected because the abstract contract yields values; `with` is the checked desugar of the Contexts row. |
| Calls | Defaults, keywords, `/`, `*`, homogeneous `*args` | Run | One structural contract serves free, method, static-method, and hand-written constructor calls in the checker and VM. A homogeneous `*args` over a loan-carrying element type (`count(Span(xs), Span(xs))` against `def count[T: Copyable](*args: T)`) binds the element's origins from the collected arguments as a regular parameter binds its own, so it runs over a read parameter or a local and a `-> T` result carries the bound origin; arguments over different origins are rejected, as upstream (`assets/ok/homogeneous_variadic_loan_carrying_element.mojo`). A collector indexed by a runtime value (`sum += xs[i]`, `xs[i].byte_length()`) reads that element on both backends, natively at a strided offset behind a bounds trap; an instance with an empty collector compiles, its guarded reads never running (`assets/ok/collector_runtime_index.mojo`). A default that is neither a literal nor an `@implicit` conversion of one (`s: String = String("a")`, `x: Int = TWO + 1`, `xs: List[Int] = List[Int]()`) lowers as a zero-parameter default function both backends run for each call leaving the slot out, on a free function, a method, and a nested `def`; natively the caller calls it, hands a `var` slot's value to the callee, and releases a borrowed slot's after the call (`assets/ok/evaluated_default_argument.mojo`). The pin evaluates a default once at compile time, so a default naming runtime storage (an enclosing local) rejects with upstream's `cannot use a dynamic value in default argument`, a raising one rejects, and one that prints or reads input rejects too (the VM-CTFE effect classifier: `docs/non-goals.md`); an effect-free default runs alike either way. A default may read a compile-time parameter in scope: the struct's through `Self` (`x: Int = Self.n * 2`), the method's or function's own (`x: Int = n`), an enclosing function's from a nested `def`, or a type parameter (`x: T = T()`); its default function declares those binders and the elaborator runs one instance per assignment of them, so each owner instance gets its own value (`assets/ok/default_reads_binder.mojo`); the `--erased` oracle refuses such a default (`docs/roadmap.md` R16). A collection display default is typed against its parameter, so `xs: List[Int] = [1, 2]` is a fresh `List` per call, not an `Array` (`assets/ok/collection_display_default.mojo`). An evaluated default handed to a borrowing parameter is not destroyed (`docs/roadmap.md` R111). |
| Calls | Homogeneous `var **kwargs` and `**kwargs^` forwarding | Run | Current declaration syntax requires consuming `var **kwargs: T` and rejects bare `**kwargs: T`; function types retain the keyword-variadic role, and callable symbols distinguish it from an ordinary parameter of the same type. Free, generic, instance, static, bounded-trait, and indirect calls materialize an owned, insertion-ordered `StringDict[T]` (keys spelled `StringLiteral` — keyword names are compile-time strings; the VM ABI is unchanged by the nominal-String takeover). Forwarding consumes it through the shared binder, specialization, duplicate, origin, ownership, and effect checks. The native backend builds the collector as the VM does — the instance's empty constructor, then one `__setitem__` per collected keyword, a borrowed heap value cloned in — so keyed reads and membership tests (`kwargs["b"]`, `"color" in options`) run natively too, through direct and indirect calls (`assets/ok/kwargs_keyed_read.mojo`). |
| Calls | Heterogeneous `*args: *ArgTypes` | Run | Per-element bound checking, an explicit checked runtime-pack ABI with private heterogeneous `Value::Tuple` storage, and compile-time `args.__len__()` iteration/indexing run for any checked argument (`b.__len__()` also answers at runtime, in the VM and natively, from the specialized pack's static arity, as `len(b)` does): a literal or a non-generic construction specializes before checking, while a local, a generic construction (`Box(7)`), or an origin-bearing temporary (`Named("k", w)`, its erased origin slot spelled `_` in the clone) is typed by the checker and minted on the next discovery round, the deferred call meanwhile checking against a signature-only stub of the template — for a pack-keyed `def` the cloner still serves (an element-typed binding under the loop, a collector-less signature spread such as `-> Variant[*Ts]`, a spread into a method; roadmap R252, R255, R256), where a module-level pack-keyed `def` outside that set — its collector read or owned — is served by its template, checked once with the collector a pack of the symbolic `Ts`, each `args[i]` the dependent `Ts[i]`, and the pack's length (`args.__len__()`, `Ts.length`, `len(Ts)`) a parameter expression bounding its `comptime for` (`assets/ok/pack_template_served.mojo`); such a `def` may spread its pack whole into `print` or into another served `def`, after a fixed positional prefix too and transferring an owned pack (`tally(10, *rest)`, `drain(*items^)`): MIR carries the call with the collector as its spread argument (`MirInstr::Call::spread`, schema 1.17), the ownership analysis sees the collector lent or moved whole, and the elaborator passes the bound pack's elements to the callee's template, on the VM and natively (`assets/ok/pack_template_served.mojo`'s `relay` and `forward_owned`, `assets/ok/pack_forwarding_print.mojo`, `assets/ok/pack_argument_destroyed_after_call.mojo`'s `outer`, `assets/ok/pack_overload_sibling_forward.mojo`); a clone that spreads its bound pack into a served `def` passes the elements itself; `len(args)` is a runtime value, as upstream, and cannot bound a `comptime for` (`assets/type_error/comptime_for_runtime_pack_length.mojo`). Before generating a specialization, the call-site conformance diagnostic identifies the one-based failing element, its concrete type, the pack, and the unsatisfied trait. A pre-check resolver assigns stable value/type binding identities, so pack spreading and type expansion respect nested definitions, lexical blocks, loops, comprehensions, sibling methods, and empty packs. Nested templates have scope-qualified identities, specialize independently at their lexical declaration, lift recursively at arbitrary depth, and preserve captures/defaults/keywords/named results. A complete forwarded pack follows the fully supplied fixed positional prefix and precedes a keyword/default tail; its private pack collector moves as one value without copying linear elements. Type and value packs may be interleaved with semantic-only `Origin`/`OriginSet` parameters; a pack consumes only its source-layout segment, so a named Origin suffix remains at the rewritten call. A second spread or explicit positional overflow after the spread is rejected, matching the pinned nightly. A pack-keyed body may also forward its pack whole into another pack-keyed method (`self.take(*a)`, after a fixed positional prefix too) or into `print` (`print(*a, sep=", ")`): each instance passes the pack element by element, and a method template whose body reads its own collector's length (`a.__len__()`) checks as a per-call clone, as one reading `Ts.length` does. One overload of a type-pack `def` may forward its pack whole to a same-named sibling (`return first + tally(*rest)`): the forward binds the one declaration whose collector the spread follows, as the pin binds it when it checks the template, and a forward that several declarations of the family would bind stays unsupported. Specialization exposes the concrete type of each statically indexed pack element; ordinary tuple-valued homogeneous variadics remain nominal `List` collectors. A read collector borrows what it gathers, as a `read` parameter does: a local outlives the call and a temporary is destroyed once the call returns, where an owning `var` collector takes its elements (`assets/ok/pack_argument_destroyed_after_call.mojo`); an element passed on to `print` or to another read parameter is read where it lies, as an element of a `Tuple`, a `List` or an `Array` is, so no copy constructor runs for the pass (`assets/ok/pack_element_read_borrowed.mojo`); a value read of a homogeneous collector's element (`var x = a[1]`) loads the element place and copies that element alone, as a field read does (`assets/ok/variadic_element_value_read.mojo`), and `len(a)` — like `len` of a named tuple — reads the storage in place and copies no element (`assets/ok/variadic_collector_len.mojo`); an element read through a `Span` still copies (roadmap R117). An owning `var` collector lives until the last use of any element read out of it, and its elements are then destroyed last to first — the reverse of a `Tuple`'s storage — for a module `def` (served by its template), a method, a homogeneous collector, and a pack nothing reads, on the VM and natively (`assets/ok/owned_pack_destroyed_in_reverse.mojo`); an element transferred out of a pack by subscript (`a[i]^`) is rejected, as the pin rejects it (`assets/type_error/owned_pack_element_transfer.mojo`); the pin destroys a heterogeneous owned pack before consuming a literal-index element read that is its last use, printing an element whose destructor already ran, and Mojito keeps consuming it first (`docs/non-goals.md`, `conformance/probes/owned_pack_literal_index_destroyed_before_use.mojo`). |
| Calls | Generic callable constraints and callable-value parameters | Run | `F: def(T) -> T` is retained as a dependent checked constraint, makes `F` callable inside the generic body, and validates a monomorphic contract against one monomorphic function type or nominal callable struct. A contract with its own `def[...]` list instead accepts an alpha-equivalent generic function, retaining binder arity, bounds, conventions, effects, reference origins, and invocation defaults. Compatibility is directional: a nonraising/read-only implementation may satisfy a raising/mutable contract, while ownership-changing conventions and reference-origin contracts remain exact. An explicit environment qualifier on the right-hand side (`callback: def(...) thin` or `capturing[...]`) declares a compile-time callable-value parameter; `OriginSet`, `capturing[_]`, `capturing[origins]`, and the infer-only `//` marker are retained, and the supplied function or closure is reified into a hidden typed runtime local for indirect calls. Callable-value defaults are symbolic selected-function, earlier-parameter, or compile-time-conditional plans evaluated in declaration order. Comptime specialization bakes the scalar/type/pack values it inspects while retaining callable and Origin arguments on the residual signature and call site; `CtValue` deliberately has no function or closure variant, and arbitrary callable CTFE is not implied. |
| Calls | Callable capture-origin contracts | Run | Checked function types distinguish unqualified, `thin`, and `capturing` environments. Materialized closures carry a canonical concrete origin set with read/write access per captured owner; `OriginSet` parameters and inference placeholders remain symbolic until a concrete callable is supplied. These dependencies participate in substitution, nominal conformance, origin escape checking, checked HIR, typed MIR declarations, and direct, indirect, method, and nominal subscript capture effects, so persistent-loan analysis sees mutations performed by a directly called closure or a non-escaping callable argument. A capturing closure no longer binds to an unqualified `def(...)` value contract — the checker rejects it with a hint naming the `capturing[...]` spelling, matching current Mojo; comptime callable bounds (`F: def(...)`) still ground capturing values, as upstream accepts. A thin (non-capturing) callable satisfies every `capturing[...]` value contract — its capture set is empty, a subset of any allowed origin set — matching upstream's acceptance of plain functions for capturing funargs. |
| Calls | Method/generic argument-binding parity | Run | Includes ordinary-parameter write-back. Explicit method-level value-parameter bindings on non-pack structs (`widget.pick[3]()`, `holder.pick[3]()` on an origin-parameterized struct, defaulted `scaled(4)` beside `scaled[10](4)`) select the per-call clone, whose baked parameters occupy no MIR argument slots; a `ref self` method on a call temporary (`s.split(",")[1]`) keeps the temporary alive through the result. |
| Calls | User-defined static methods | Run | Uses the same positional/default/keyword ABI without a receiver slot. An instance method called through its type takes the receiver as the first argument, as upstream (`List[Int].__len__(xs)`, `Point.shift(p, 10)`, `Optional[Int].value(opt)`): with no static of that name, the call checks and lowers as `xs.__len__()`, and a receiver whose type arguments disagree with the application is rejected (`List[String].__len__(xs)`). On a parameterized struct, a static dispatches through an explicit `Dict[Int, String].fromkeys(...)` receiver or a bare `Dict.fromkeys(keys, 0)` receiver whose struct parameters are inferred from the argument types (defaults such as `H: Hasher = default_hasher` fill in); `Self` in the signature resolves to the instantiated struct, and overloads — including same-arity pairs — run their checker-selected symbols on both backends. An explicit receiver application partitions its origin slots as construction does (`View[origin_of(w)].make(w)`, `Span[Int, origin_of(xs)]`); a static binding `ref [Self.o]` arguments is a constructor in all but name — the explicit origin is checked against the binding argument and the result keeps it lent — and every static retains its `mut`/`ref` argument places and alias-checks like an instance call. A static's own compile-time parameters apply explicitly on every receiver spelling — a plain struct's bare name (`Lanes.ident[Int](3)`), the single-argument application that parses as a value subscript (`Box[String].ident[Int](3)`), and a type application (`Box[Int].ident[Int](3)`) — with a type or `DType` key, a `comptime if` folding on it, and the same per-call clone the inferred spelling mints (`assets/ok/static_method_explicit_application.mojo`). |
| Calls | Callable expressions / first-class function values | Run | Non-capturing, generic, origin-specialized, and contextually selected overloaded functions can be stored, passed, and indirectly invoked with checked raising and capture effects plus reference returns. Explicit Origin arguments participate in direct overloaded and generic calls, combine with explicitly supplied ordinary generic arguments in function values, and select an overloaded function value when an expected `def(...)` type identifies one candidate; an uncontextualized overloaded value remains ambiguous. User structs are callable only when they nominally conform to a matching `def(...)` contract and implement `__call__`; callable generic parameters, environment constraints, `mut`/`ref` conventions, origin-bearing results, the receiver place, and the exact signature-qualified `__call__` target survive conformance and indirect lowering, including same-arity overload sets. A same-arity method overload whose parameter is the enclosing struct type keys as `$ov$Self` on both the declaration and call sides however it is spelled (bare `Self` or the explicit self-application `List[Self.T]`), so a `def m(self, other: Self)` beside `def m(self, n: Int)` dispatches to the right definition instead of failing at the VM. Captured nested Origin specialization remains a documented Mojito extension over the pinned nightly. |
| Calls | Named `out` results | Run | A free function's single `out` parameter is a caller-transparent result slot and must be initialized before fallthrough or bare return. |
| Conventions | `imm`/legacy `read`, `var`, `mut`, `ref` parameters and `ref self` | Run | `imm` and its temporary compatibility synonym `read` share immutable-reference semantics. A bare aggregate variable passed to a read-convention or `mut`/`ref` parameter binds as a shallow place read — no argument-side `__copyinit__` runs, matching Mojo's borrow (consuming `var`/`deinit` passes still run the copy lifecycle; field-chain and reference-result actuals already read shallowly). The builtin `print` binds its positional arguments the same way: a named struct- or type-parameter-typed value is read in place, and an owned temporary (`print(x.copy())`, `print(IC(5))`) is destroyed once `print` returns (`assets/ok/print_argument_read_in_place.mojo`). Copyable immutable arguments overlapping a `mut`/`ref`/`^` access in the same call are materialized through the implicit copy that satisfies exclusivity; non-Copyable aliases remain errors. |
| Conventions | `out self`, named `out` results, `deinit self`, owned-`var` transfer | Run | Lifecycle receivers and a single free-function named result are supported. Consuming positions — `var`/`deinit` parameters and receivers, operator `var` operands (`p + q` on `List`), variable initialization, assignment, field stores, returns, displays, and constructor arguments — accept a *place* only when its type is `ImplicitlyCopyable`; otherwise spell `^` (a mutable or owned binding) or `.copy()`. A static method's `var` parameter makes the same demand as an instance method's (`assets/type_error/implicit_copy_static_var_argument.mojo`); an owned `var *args` collector makes it of each place it gathers, on the free, method, static and constructor paths, and a tuple display or `Tuple(…)` reaches `Tuple`'s own collector (`assets/type_error/implicit_copy_variadic_var_collector.mojo`, `assets/type_error/implicit_copy_tuple_display_element.mojo`). There is no last-use move: `take(a)` rejects even when `a` is dead afterwards, as upstream. A non-`ImplicitlyCopyable` read overlapping a `mut`/`ref` access in the same call is an aliasing error rather than a hidden copy, and a *read* of a nominal value (including `String`) never disarms exclusivity by copying — `bump(mut s, s)` on a `String` is rejected. A consuming `var`/`deinit` slot does copy the place out before the callee runs, so it never overlaps: `bump(mut s, var s)`, and the element store `xs[i] = xs[j]` it underlies, are accepted for every element type. A borrowing view conversion (`var s: Span[Int, _] = xs`) consumes the conversion temporary, not the source place; a temporary source (`f(String("abc"))` at a `StringSpan` parameter, or the receiver of a view-returning method — `String("abc").codepoints()`, `.__reversed__()`, `.as_bytes()`, `.split(",")`) materializes in a hidden owned slot the view borrows, living as long as the view, so such a view cannot be returned. Every other owning temporary is destroyed as soon as its consumer finishes, running its `__deinit__` where the pinned Mojo does: the receiver of a method (`B(3).show()`, `print(B(2).get())`, a chained `B(5).twin().show()`) right after that call returns, before the enclosing expression continues; an argument at a read parameter (`take(B(2))`, positional or keyword) once the callee returns; and a temporary read for a field (`print(B(1).x)`, `var n = B(9).name`) after the instruction consuming the field, an owning field being copied out first. A `var`/`deinit` receiver or parameter takes the temporary and destroys it in the callee. |
| Lifecycle | `Deinitable`/`__deinit__`, unified copy/move initialization, and `@implicit` constructors | Run | Ordinary values are implicitly deinitable; an explicitly false conditional conformance makes a type linear. A field typed by a bare struct type parameter (`var value: Self.T`) needs a bound proving `Deinitable` (the trait, a trait refining it, or `TrivialRegisterPassable`) unless the struct declares a `Deinitable` conformance, conditionally or not, which discharges it (`field 'value' has non-'Deinitable' type 'T'`, as upstream). The upstream-deprecated `ImplicitlyDeletable`/`__del__` spellings are accepted and normalized to the canonical vocabulary at parse time (removed when upstream removes them). A declared conditional `Movable` conformance is effective: `Movable where False` rejects `^` transfers, `var` parameters/receivers, and move/copy captures, while `deinit` consumption (destructors, named destructors) stays legal and Copyable pass-by-value is unaffected. A bare `move:` initializer parameter is rejected with a migration diagnostic naming the `deinit move: Self` spelling. `Copyable` carries current Mojo's non-overridable default `copy()`: elaboration synthesizes `def copy(self) -> Self` on every struct declaring `Copyable`/`ImplicitlyCopyable` that does not spell its own, delegating to a declared `__init__(out self, *, copy: Self)` (run exactly once per copy — the construction reads its source as a retained borrowed place) or falling back to the fieldwise copy lifecycle, with a conditional conformance's predicate carried over as the method's `where` clause; a `Copyable`-bounded parameter resolves the same `copy() -> Self` contract whenever its copyability is proven (a refining bound, a member bound, or a `conforms_to(T, Copyable)` availability clause), and `copy()` on a built-in copyable value (scalars, literals, tuples, variants) is the value read itself. `ImplicitlyCopyable` may be declared alongside an explicit `__init__(out self, *, copy: Self)` — the explicit initializer is then the conformance, as for upstream `String`; without one every field must be `ImplicitlyCopyable`. `String`, `Codepoint`, and `Optional[T]` where `T` is `ImplicitlyCopyable` conform. |
| Lifecycle | `@explicit_destroy` | Run | The required string argument customizes linearity diagnostics but does not itself make a type linear. Named `deinit self` methods discharge path-sensitive obligations. A `var` parameter or local typed by a type parameter (or a dependent pack projection) whose bounds do not prove `Deinitable` is linear too, as upstream: abandoning it reports `abandoned without being explicitly destroyed: unhandled explicitly destroyed type 'AnyType'` (the pin names the parameter's own bound there). So is a call result of that type in a position that takes no ownership of it — an argument the callee only borrows, an argument of `print`, a discarded expression statement — reported as `'(expression temporary)'` abandoned.
